# Visual source authority: Shard-God Tiger

## Authority hierarchy

1. **PRIMARY: `assets/references/tiger_original_canonical.jpg`**. The user designated the original Tiger image canonical. It is the structural authority for face, snout shape, chin, silhouette, anatomy, crystalline adornments, and coloration.
2. **PROVISIONAL: `assets/references/tiger_expressions_provisional.jpg`**. This image labels 12 expression concepts, but itself says `PROVISIONAL VISUAL REFERENCE` and portrays some head geometry with a different/elongated shape. Do not treat it as an approved redesign or source for exact rig anatomy.
3. No unreviewed model outputs, prompts, or third-party examples may override (1).

## User-locked rendering facts

- Tiger is the Shard-God Tiger, an approximately **9-foot-tall** fictional entity.
- Preserve the **original head shape** exactly rather than morphing to a longer dragon-like or human form.
- Eyes have **NO PUPILS**. Do not add irises, pupils, human teeth/lips or facial muscles to satisfy a face detector.
- Preserve the angular/faceted obsidian-like dark body, cyan luminous fissures and shard/crystal morphology.
- No clothing, cape, or generic fantasy-dragon substitute. Don't invent legs, tails or body components not in source where source is authoritative.
- The original uploaded image is 1024x1536 JPEG; expression reference 1536x1024 JPEG even though the upload name was `.png`.

## Rig protocol

- Preserve source image unchanged. Place all animation geometry on separately editable overlay layers.
- User must author/approve canonical neutral, open, round, clenched, and intermediate mouth drawings for any Tiger-specific final export. Until then allow **draft** test rig only clearly flagged unapproved.
- Allow manual placement with anchors relative to the original head. Keep edits transformable/reversible; no destructive painting into original image.
- For nonhuman profiles generally, mouth pose semantics map to visible articulation, not human anatomy.
- `assets/references/SOURCE_MANIFEST.json` holds file hashes; verify before and after development and distribution.
